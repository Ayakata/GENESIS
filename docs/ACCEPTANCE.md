# Приёмка Sprint 01

Условия проверяются до изменения чекбоксов в `GENESIS_ROADMAP.md`.

## S01-1

- Пакет устанавливается editable и из wheel; CLI доступен как `genesis` и `python -m genesis`.
- `init` создаёт полный YAML; `validate` читает его и печатает разрешённые значения.
- Неизвестные ключи/схемы, некорректные типы/диапазоны и дубликаты отклоняются.
- Одна документированная последовательность создаёт окружение, запускает тесты и опыт.
- Ruff lint/format и mypy strict проходят; wheel/sdist собираются.
- Тестовый CLI работает из отдельного процесса, ошибки дают код 2, результаты не затираются.

## S01-2

- 2D-поля генерируются из seed, имеют форму `[height,width]`; миры не делят массивы/RNG.
- Два отдельных процесса с одинаковым config дают одинаковые digest и метрики.
- Разные seeds изменяют мир; потребление agent-stream не изменяет stream среды.
- Closed/periodic края и непроницаемая вода проверены известным импульсом и барьером.
- Диффузия сохраняет сумму и неотрицательность, включая 1x1, 1xN, 2x2 и d=0.25.
- При отсутствии источника/потерь сумма сохраняется; decay=1 удаляет весь ресурс в ledger.
- Одноклеточная система совпадает с аналитическим решением рекуррентного уравнения.
- На 3 seeds, в двух краевых режимах и в закрытом контроле нет NaN/Inf/отрицательных полей;
  абсолютный остаток баланса <1e-8 в контрольном сценарии 96x64/200 тиков.
- Разрешённый конфиг, seed, версия правил/схем, fingerprint кода и зависимости сохранены.

## S01-3

- Агенты хранятся в типизированном SoA без Python-объекта на каждую особь.
- Начальное размещение, движение, питание, размножение и смерть детерминированы seed.
- Агент никогда не оказывается вне карты или на воде; periodic/closed границы соблюдаются.
- Потребление клетки не превышает доступный ресурс и честно делится между конкурентами.
- Метаболизм, успешное движение, неполное усвоение, размножение и смерть имеют явные статьи.
- Размножение переносит энергию потомку, сохраняет parent id и не создаёт энергию.
- При смерти заданная доля возвращается в клетку, остаток фиксируется как потеря.
- Ресурсный, агентный и совокупный остаток <1e-8 в длительных сценариях.
- Повторы 3 seeds × 2 режима границ в отдельных процессах дают одинаковые digest/метрики.
- В NPZ сохраняется инспектируемое конечное состояние агентов; resume остаётся S01-6.

## S01-4

- В SoA хранится ровно восемь именованных количественных генов `float64` в `[0,1]`.
- Одинаковый seed воспроизводит начальные геномы, мутации, фенотипы и полную траекторию.
- При `mutation_rate=0` потомок получает побитово точную копию без потребления RNG.
- При включённых мутациях изменения независимы по локусам, конечны, ограничены `[0,1]`
  и отражаются в счётчиках mutated/clipped loci и mutated offspring.
- Parent id и геном позволяют проверить непосредственное наследование.
- Размер, скорость, сенсорика, метаболизм, исследование, осторожность, размножение и
  эффективность реально влияют на механику; выгоды имеют энергетическую/поведенческую цену.
- Генетические метрики являются наблюдением и не используются как внешний fitness.
- Контроль с идентичными основателями и без мутаций сохраняет нулевую вариативность;
  мутационный режим создаёт ограниченную ненулевую вариативность минимум на 3 seeds.
- 6 повторных пар отдельных процессов совпадают при разных `PYTHONHASHSEED`; лимит
  популяции не достигается, совокупный энергетический остаток остаётся <1e-8.
- Результат не называется адаптацией: контрастные среды и отбор проверяются в S01-8.

## S01-5

- CLI принимает один или несколько именованных сценариев и список уникальных seeds.
- Матрица `scenario × seed` имеет стабильный порядок и отдельный каталог для каждой задачи.
- `jobs=1` и process-parallel `jobs>1` дают одинаковые digest и научные метрики.
- Процессы используют `spawn`; конфиги и RNG не разделяются между независимыми мирами.
- Небезопасные/повторные имена, повторные seeds, неверное число workers и слишком большой
  план отклоняются до создания выходного каталога.
- Существующие результаты не перезаписываются; batch manifest различает running/completed/failed.
- Сохраняются полный resolved config и обычные артефакты каждого запуска, общий план,
  результаты, версии/окружение и wall-clock производительность.
- Отдельный in-memory benchmark имеет warm-up и повторы; все повторы дают один digest,
  а отчёт содержит ticks/s, cell updates/s и agent updates/s.
- Производительность конечна и положительна, но машинозависимое число не используется
  как переносимый порог или часть научного состояния.

```bash
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m build --no-isolation
python experiments/s01_environment/reproduce.py --output runs/acceptance
python experiments/s01_agents/reproduce.py --output runs/agents-acceptance
python experiments/s01_evolution/reproduce.py --output runs/evolution-acceptance
python experiments/s01_headless/reproduce.py --output runs/headless-acceptance
```

`experiments/s01_*/evidence/` и `docs/PROGRESS.md` содержат фактический
результат, версии и ссылку на проверенный implementation commit. Проверки не
подтверждают эволюцию, адаптацию или возникновение жизни — эти критерии впереди.
